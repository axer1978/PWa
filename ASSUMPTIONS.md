## Session engine (Phase 1)

| #    | Status | Item                                                                                                                                                                                                                                                                                                                                                                               |
| ---- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S-01 | 📌     | **Timer semantics.** The prompt says "auto-advance after N seconds unless the user taps". Read as: the clip loops for `timeoutMs`, then the session goes to `defaultTarget`; a tap before then goes to `next` (or to `defaultTarget` early if there's no `next`). The timeout counts from when the node starts.                                                                    |
| S-02 | 📌     | **Choice clip** loops as a bed while waiting. An optional `timeoutMs` + `defaultTarget` pair auto-picks; the schema requires both or neither.                                                                                                                                                                                                                                      |
| S-03 | 📌     | **Cycle rule** (the prompt: "cycles without a loop/choice exit"). Every cycle needs an edge leaving it from a `choice`, `loop` or **`timer`** node. Timers count too: a timer's timeout leaves the cycle without the listener's help. Cycles that can only be left through a `play` node's conditional `next` are rejected, because nothing guarantees the condition ever changes. |
| S-04 | 📌     | **Reachability is structural**: every branch of a conditional edge counts, whatever the state. A branch whose condition can never hold is not detected.                                                                                                                                                                                                                            |
| S-05 | 📌     | **State** is declared in the session's `state` object (initial values). Options may only `set`, and conditions may only test, declared keys with the declared type. Only `set` exists; there's no arithmetic. Ordering operators (`gt`/`gte`/`lt`/`lte`) need numbers.                                                                                                             |
| S-06 | 📌     | **Nodes are an array with explicit `id`s**, not an object keyed by id. `JSON.parse` silently drops duplicate keys, but duplicates in an array can be detected (`duplicate-node`).                                                                                                                                                                                                  |
| S-07 | 📌     | **Access** is `free` or `paid` in the session file. Which paid sessions a pack unlocks lives in the plans config (Phase 5), so each fact has a single source.                                                                                                                                                                                                                      |
| S-08 | 📌     | Ids and `clipId`s are restricted to `^[a-z0-9][a-z0-9_-]{0,63}$`. A clip id maps straight to a file or CDN path, so traversal (`../`) is impossible by construction.                                                                                                                                                                                                               |
| S-09 | 📌     | Each session file must be named after its id (`sessions/<id>.json`). That rules out duplicate session ids.                                                                                                                                                                                                                                                                         |
| S-10 | 📌     | **Placeholder audio:** mono 48 kHz, Opus 64 kbps VBR in Ogg (`.opus`) and AAC-LC 64 kbps in MP4 (`.m4a`, `+faststart`). Clips the player loops (choice, timer, loop) use integer-Hz tones over whole-second durations, so they loop without a click.                                                                                                                               |
| S-11 | ⚠️     | `make-placeholder-audio.sh` has only been run against a stub `ffmpeg` (argument handling, skip/force, atomic rename). Real encoding, including the `aevalsrc` expressions, first runs in CI or once ffmpeg is installed locally. CI then checks codec, channels and sample rate with `ffprobe`.                                                                                    |
| S-12 | 📌     | The validator checks clips against a local directory (`--clips`, default `content/audio`). In production clips live on Bunny, so the content workflow is: validate locally against the files, then sync them to Bunny (Phase 3 / `RUNBOOKS.md`).                                                                                                                                   |
